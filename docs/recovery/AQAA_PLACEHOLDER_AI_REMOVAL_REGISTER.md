## Placeholder Systems Identified at Recovery Sprint Start

### 1. SHA-256 Hash Embeddings

| Field | Value |
|-------|-------|
| File | `backend/app/knowledge_indexing/embedding_service.py` |
| Class | `PlaceholderEmbeddingService` |
| Flag | `IS_PLACEHOLDER = True` |
| Dimensions | 384 |
| Behaviour | Deterministic SHA-256 hash of text, cast to float vector. No semantic meaning. Search results are essentially random. |
| Config trigger | `USE_REAL_EMBEDDINGS=false` (was the default) |
| **Status** | **REPLACED** — `FastEmbedEmbeddingService` now active. `IS_PLACEHOLDER=False`. |

### 2. LOCAL_DEV AI Provider (Template Assembly)

| Field | Value |
|-------|-------|
| Setting | `AI_PROVIDER=LOCAL_DEV` in `backend/.env` |
| Behaviour | Template string assembly. No LLM call. `is_local_dev=True`. Answer is a formatted list of retrieved knowledge chunk titles. |
| Config trigger | `AI_PROVIDER=LOCAL_DEV` |
| **Status** | **PARTIALLY REPLACED** — `.env` now has `AI_PROVIDER=OPENAI`. OpenAI key has `insufficient_quota` so the provider chain falls back to `LOCAL_DEV` at runtime. Real LLM answers require a funded OpenAI key or a working alternative (Anthropic, Ollama, Gemini). |

### 3. Stale DEV_MODE_NOTICE in Template Answers

| Field | Value |
|-------|-------|
| File | `backend/app/ai_assistant/assistant_service.py` |
| Variable | `DEV_MODE_NOTICE` (from `prompt_templates.py`) |
| Behaviour | Was unconditionally appended to all LOCAL_DEV template answers, stating "hash-based placeholder embeddings" even after real embeddings were active. |
| **Status** | **FIXED** — Now conditionally appended only when `embedding_service.IS_PLACEHOLDER` is True. |

## Remaining Placeholder Items

### AI Provider (Not Yet Resolved)

The AI answers are still generated by template assembly (LOCAL_DEV) because the OpenAI key has no billing. To fully remove this placeholder:

**Option A — Fund the OpenAI key:**
- Add billing at platform.openai.com for the key in `backend/.env`
- `AI_PROVIDER=OPENAI` is already set; it will activate automatically

**Option B — Use Ollama (local LLM):**
- Install Ollama on the host
- Pull a model: `ollama pull qwen3:8b`
- Set `AI_PROVIDER=OLLAMA`, `OLLAMA_BASE_URL=http://host.docker.internal:11434`
- No API cost; runs locally

**Option C — Use Anthropic:**
- Set `ANTHROPIC_API_KEY` in `.env` (currently blank)
- Set `AI_PROVIDER=ANTHROPIC`
- `ANTHROPIC_MODEL=claude-haiku-4-5-20251001` is already configured

**Option D — Fix Gemini key:**
- The `GEMINI_API_KEY` has an unusual format (`AQ.Ab8R...`). Standard Google AI keys begin with `AIza`.
- Obtain a valid key from Google AI Studio
- Set `AI_PROVIDER=GEMINI`
