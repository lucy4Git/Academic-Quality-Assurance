# AQAA Sprint E0 — Data Boundary and Data-Readiness Register

**Date:** 2026-07-20
**Branch:** `feature/phase-e-sprint-e0`
**Prepared by:** AQAA Engineering — Data Governance Lead

> Real institutional or personal data is **prohibited** until OD-01 (Information Officer and DPIA) and OD-02 (Pilot institution confirmed) are both resolved. This register is a binding data-use policy for all Sprint E0 through Phase E development.

---

## 1. Permitted Data Classes (Current Development)

The following data classes are permitted for use in development, testing, and demonstration environments at any sprint:

| Class | Definition | Examples | Permitted from |
|-------|-----------|---------|---------------|
| **SYNTHETIC** | Artificially generated data with no connection to real individuals or institutions | Faker-generated names, randomly constructed module codes, programmatically generated finding text | Any sprint |
| **PUBLIC** | Data published openly by regulatory bodies or institutions for public use | CHE HEQSF documents from che.ac.za, DHET policy PDFs from dhet.gov.za, SAQA NQF descriptors from saqa.org.za | Any sprint |
| **ANONYMISED** | Real data that has been irreversibly stripped of all personal identifiers per established anonymisation standards | Aggregated compliance statistics with institution names replaced by codes | Any sprint (must verify anonymisation is irreversible) |
| **DEVELOPMENT_FIXTURES** | Pre-defined test records created by AQAA Engineering with no connection to real entities | Seeded GFU and RCT institutions, seed users with `ChangeMe123!` password | Any sprint |
| **APPROVED_TEST_DOCUMENTS** | Documents approved for test use — public regulatory frameworks, synthetic module folders, AQAA Engineering–generated evidence samples | Synthetic lecture attendance registers, fabricated assignment briefs | Any sprint |

---

## 2. Prohibited Data Classes (Until OD-01 and OD-02 Resolved)

The following data classes are **strictly prohibited** in all AQAA environments until both OD-01 and OD-02 are resolved and a DPIA has been completed:

| Class | Why prohibited | Condition to unblock |
|-------|---------------|---------------------|
| Real student records (name, ID, marks, attendance) | Contains personal data — POPIA requires lawful basis and DPIA | OD-01 (DPIA + Information Officer) |
| Real staff records (name, employment, evaluations) | Contains personal data — employment category | OD-01 |
| Personal identifiers (SA ID number, passport, date of birth) | Sensitive personal information under POPIA | OD-01 |
| Confidential institutional evidence (actual submissions, assessments) | Institutional IP + may contain student personal data | OD-01 + OD-02 |
| Examination content (actual exam papers, marking memos) | Institutional IP; academic integrity | OD-01 + OD-02 |
| Unpublished accreditation submissions | Institutional IP + regulator confidentiality | OD-01 + OD-02 |
| Real disciplinary records | Sensitive personal data — special category | OD-01 |
| Health information | Special category personal data under POPIA | OD-01 |
| Protected regulator correspondence | Confidential regulatory communication | OD-01 |
| Real financial data (fees, grants, budgets) | Institutional financial data | OD-01 + OD-02 |

**Enforcement mechanism:** `Institution.is_demo = True` is set on all GFU and RCT seed institutions. The data boundary register is presented to all AQAA Engineering team members as a binding policy. Violation must be reported to the project lead immediately.
